# Raster exports — WebP

Nothing in this directory is committed. Every file here is generated by CI from
the PNGs in `../png/`, which are themselves generated from the SVG masters, so a
fresh clone finds this directory containing only this README. That is the correct
state and not a failed build.

Generate them locally with:

```bash
pip install -r tools/requirements.txt   # needs Cairo: apt-get install libcairo2
python3 tools/build_exports.py --raster
```

The `--raster` step writes both directories. There is no WebP-only flag, because
a WebP produced from a PNG that was not also written would be a raster with no
sibling to disagree with and no way to notice.

## What this directory contains after a build

The same nine stems as `../png/`, at the same pixel dimensions:

```
viavitae-logo-vertical@1x.webp    @2x    @3x
viavitae-logo-horizontal@1x.webp  @2x    @3x
viavitae-logomark@1x.webp         @2x    @3x
```

See `../png/README.md` for the table of exact widths and the reason there are
three densities.

## Settings, and why these

Encoded at `quality=90` with `method=6`. `method` is the encoder's
effort/compression trade-off and 6 is its maximum: it costs CPU at build time
and saves bytes forever after, which is the right way round for an asset that is
generated in CI and downloaded by every visitor. `quality=90` on a flat-colour
logo is visually lossless — the mark is one colour, one stroke weight and no
gradient, so there is almost nothing for the encoder to discard.

WebP is not offered as a replacement for PNG here and both sets are built. A
logo is the one image on a page that is fetched early, cached forever and drawn
over other content, and the formats differ in ways that matter differently by
context: WebP is smaller, PNG is lossless and universally readable by design and
print tooling. Serving a `<picture>` element with a WebP source and a PNG
fallback is the pattern; shipping only one of them forces a compromise somewhere.

## Transparency

The three masters in `assets/logo/master/` are drawn on a transparent artboard
and both formats preserve the alpha channel, so a lockup can be placed on any
light ground without a white box around it. That is deliberate and it is also the
reason the inverse variants exist: transparency solves the artboard, not the
contrast. On a navy ground the primary lockup is navy on navy and no amount of
alpha fixes it. Use `assets/logo/inverse/`.

Note that the icon set in `assets/favicon/` is the opposite case: those files are
built from a master that carries an opaque plate, precisely because a favicon is
composited over browser chrome the brand does not control. See that directory's
README.
